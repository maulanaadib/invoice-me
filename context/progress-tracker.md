## Architecture Decisions

- Modular monolith + pdf-service terpisah (Playwright Chromium isolasi runtime).
- decimal.js + Prisma Decimal untuk semua nominal; server recalculation wajib.
- Next.js App Router + Better Auth (username/email, no public registration).
- Docker Compose (app + postgres + pdf-service) deploy via Coolify, auto-deploy on push main.
- Tracer Bullet vertical slices, GA tier (test suite wajib per feature).
- Repository: https://github.com/maulanaadib/invoice-me, branch main, 1 commit per feature.
- Central permission matrix hanya di `modules/permissions` — role string tidak pernah di-inline di service lain.
- Semua penulisan AuditLog lewat helper `modules/audit` (sanitasi metadata otomatis, tidak pernah menyimpan password/token).
- Workspace aktif via session active org (`session.activeOrganizationId`), membership di-re-validasi setiap read (fail closed).
- StorageService interface (`modules/storage`) dengan LocalStorageService — DI siap S3/MinIO, MIME sniff dari isi file (magic bytes), filename random `crypto.randomUUID`, path traversal safe, sha256 dicatat.
- Nomor rekening encrypt at rest: AES-256-GCM (`modules/bank-accounts/crypto`), format simpanan `iv:tag:ciphertext` hex, masking `**** **** 3449` hanya dari nilai terdekripsi server-side.
- Number pattern token parser (`modules/profiles/number-pattern`) satu source of truth untuk validasi + preview — dipakai server action dan client preview (token: `{CODE}` `{TYPE}` `{YYYY}` `{YY}` `{MM}` `{DD}` `{ROMAN_MONTH}` `{SEQ:n}`, tepat satu SEQ wajib).
- Soft delete customer: `deletedAt` hanya di tabel Customer (fitur 03) — row dan PIC tetap tersimpan untuk audit, semua read path menyaringnya.
- billedToDate defer ke feature 05 (fitur 03): project detail menampilkan placeholder jujur, tidak forward-reference tabel Invoice.
- Feature 05: numbering pakai isolation SERIALIZABLE + retry (maks 3, backoff) di atas `LOCK TABLE "InvoiceSequence" IN EXCLUSIVE MODE` — antrean diambil SEBELUM snapshot MVCC dibentuk sehingga waiter bangun dengan snapshot segar (tanpa itu semua pengikut abort 40001 dan retry habis), row lock `SELECT ... FOR UPDATE` + unique constraint tetap safety net lintas instance.
- Feature 05: snapshot read-after-issue — tujuh snapshot (issuer/customer/contact/bank/signer/calculation/template) dibangun saat issue dan menjadi satu-satunya sumber baca dokumen terbit; edit profil/customer/bank sesudah issue tidak mengubah invoice (bank tersimpan dalam bentuk masked, tidak ada nomor rekening plaintext).
- Feature 05: REVISED (dan DRAFT/CANCELLED) di-exclude dari previouslyBilled/billedToDate lewat satu modul `modules/invoices/billed.ts` — pasangan revisi tidak pernah double-count.
- Feature 05: PdfJob enqueue-only — issue membuat baris PENDING dalam transaksi yang sama; worker render = feature 06 (UI hanya menampilkan status antrean yang jujur, tanpa tombol unduh palsu).
- Feature 06: pdf-service **fetch print route** dengan signed token (bukan HTML inline) — token auth terpakai ujung-ke-ujung dan HTML selalu berasal dari app.
- Feature 06: page number `Halaman {n} dari {total}` + baris referensi via **Playwright `displayHeaderFooter` footer template** (footer engine, bukan statis) — template tidak mewarisi CSS halaman, jadi seluruh style inline.
- Feature 06: **worker interval di app container** (`src/instrumentation.ts`, sekali per proses server, `PDF_WORKER_ENABLED` untuk mematikannya di test) — claim atomik `FOR UPDATE SKIP LOCKED` + retry cooldown; single instance cukup untuk MVP.
- Feature 06: **PDF official immutable** — file disimpan (path `invoices/organizations/{orgId}/{year}/{nomor}.pdf`), `InvoicePdf` version+sha256 isOfficial; tidak pernah render ulang (edit profil setelah terbit tidak mengubah file lama — diuji).
- Feature 07: **`recomputePaymentStatus` pure function** (`modules/payments/status.ts`) — satu-satunya tempat keputusan status pembayaran (0/partial/full/overpayment + guard DRAFT/CANCELLED/REVISED/OVERDUE → LOCKED), tanpa I/O sehingga unit-testable dari tabel input; `remainingAfter` di-floor 0 (kelebihan bayar tampil sebagai `amountPaid` > grandTotal).
- Feature 07: **record payment transaksional** — row lock `SELECT ... FOR UPDATE` pada invoice, `amountPaid` dihitung ulang sebagai SUM baris `Payment` (tidak pernah menerima angka dari client), update `amountPaid`/`remainingAfter`/`status` + audit `PAYMENT_RECORDED` dalam satu `$transaction`; upload bukti terjadi di luar tx dan dibersihkan best-effort bila tx gagal (storage tidak transactional).
- Feature 07: **reversal = OWNER/ADMIN + audit metadata** — `deletePayment` memakai permission `payment.delete` (matriks: OWNER/ADMIN saja), menghapus row + file bukti, recompute dari sisa baris, dan menulis audit `PAYMENT_RECORDED` dengan `metadata: { reversed: true }` (bukan action enum baru); alasan override overpayment disimpan di baris `overpaymentReason`, audit hanya menyimpan `reasonLength` (mengikuti pola alasan cancel — tanpa free text).
- Feature 07: **overpayment dikonfirmasi sesuai role** — STAFF wajib `confirmOverpayment`, OWNER/ADMIN wajib `overpaymentReason` (permission `payment.override`), keduanya divalidasi ulang di server di dalam tx; status PAID bisa terjadi dengan `amountPaid` > grandTotal, `remainingAfter` tetap 0.
- Feature 07: **konstanta yang dipakai server jangan diimpor dari module `"use client"`** — impor `PAYMENTS_PAGE_SIZE`/`CUSTOMERS_PAGE_SIZE` dari komponen tabel ke page server menghasilkan client reference (bukan angka) → `pageSize` NaN → error Prisma; letakkan konstanta di module client-safe (feature 07: `modules/payments/schema.ts`).
- Feature 07: filter nomor invoice di `/payments` hanya mencocokkan `number` (nomor final) — `numberPreview` sengaja tidak dicari karena preview invoice N = nomor invoice N+1 (bisa menarik pembayaran invoice lain).
- Feature 08: **server-side pagination/filter/sort lewat `modules/invoices/query-service.ts`** — URL adalah state (back/forward + share reproduksi tampilan), sort memakai whitelist kolom + tiebreaker stabil, dan **status efektif** (OVERDUE on-read) dipakai bersama oleh filter dan badge sehingga list tidak pernah menampilkan baris yang berbeda arti dengan filternya; baris di luar filter = empty state yang menjelaskan, bukan halaman kosong.
- Feature 08: **row action = reuse service fitur 04/05/06/07, tanpa service baru** — `InvoiceRowPermissions` dihitung di server sebagai *permission ∧ guard status* (mis. `markSent` hanya `status === ISSUED`, `downloadPdf` hanya `pdfPath` ada, `recordPayment` hanya status payable) sehingga menu tidak pernah menawarkan aksi yang akan ditolak service; client hanya me-render flag.
- Feature 08: **permission-aware menu** — `nav-config.ts` memegang `requires` per link, layout server menghitung flag dari `can()` (matriks pusat), shell menyaring; role string tidak pernah inline, dan link ke route yang belum ada tidak pernah ditambahkan (anggota tim/pengaturan/rekening bank menyusul bersama fiturnya).
- Feature 08: **uang keluar selalu 2 desimal** — `_sum` Prisma menghasilkan `Decimal` tanpa trailing zero (`"10500000"`), jadi query-service dan dashboard mem-normalisasi lewat `roundMoney` sebelum sampai ke komponen (kontrak yang sama dengan `lib/money`).
- Feature 09: **audit-on-view untuk admin invoice access** — `adminViewInvoice(invoiceId, ctx)` menulis `ADMIN_VIEWED_INVOICE` sebelum data dikembalikan, dan download PDF dari panel admin menulis `PDF_DOWNLOADED` dengan metadata actor admin; super admin adalah satu-satunya pengecualian org isolation dan setiap view sensitifnya tercatat (invariant 7 + security-standards).
- Feature 09: **UploadRecord table untuk storage aggregation** — tabel minimal (`organizationId`, `path` unique, `sizeBytes`, `mimeType`, `kind`, `createdAt`) mencatat setiap upload baru, dan `delete()` di StorageService menghapus barisnya; total usage per org = Σ `InvoicePdf.sizeBytes` + Σ `UploadRecord.sizeBytes` (pilihan spek: sum dari record DB, bukan scan untuk menjumlah).
- Feature 09: **admin guard defense-in-depth** — tiga lapis: `src/proxy.ts` (redirect `/unauthorized`), layout/page `app/admin/*` (cek `session.user.platformRole`), dan service layer `modules/admin` (lempar `FORBIDDEN` untuk non-SUPER_ADMIN sebelum ada query) — diuji langsung di unit test service.
- Feature 09 (diratifikasi engineer): **suspend organization = blokir login + mutasi baru saja** — baca/tetap data tetap diizinkan, tidak ada data freeze. Login: user dengan ≥1 membership aktif yang semuanya di org tersuspensi ditolak 403 di `interceptSignIn` (pola sama dengan blokir user SUSPENDED); mutasi: status org masuk ke `PermissionContext` dan `can()` pusat `modules/permissions` menolak **aksi non-read** saat org SUSPENDED (daftar read-action eksplisif: `*.view`, `invoice.download/preview/export`, `invoice.draft.read`, `report.view`) — tanpa mengubah service per service.
- Feature 09 (diratifikasi engineer): **3 nilai AuditAction baru (migrasi additive)** — `USER_ROLE_CHANGED` (assign/ganti platform role), `ORGANIZATION_STATUS_CHANGED` (suspend/aktivasi organisasi), `PDF_JOB_RETRIED` (retry job PDF gagal), sehingga kontrak architecture-context "setiap aksi super admin tercatat" terpenuhi; daftar kanonik di `data-model.md` ikut diperbarui (mengikuti jejak feature 01 yang menambah nilai enum).
- Feature 09 (diratifikasi engineer): **reconcile UploadRecord otomatis sebelum total storage** — halaman/layanan storage memindai folder `uploads/organizations/*` dan meng-upsert baris yang belum ada (idempoten per `path`, mime dari ekstensi yang memang dihasilkan kode upload) sebelum menjumlahkan; upload/hapus baru tetap direkam saat terjadi. Angka akurat tanpa langkah manual di dev maupun prod.
